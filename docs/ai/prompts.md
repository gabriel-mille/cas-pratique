# Prompts IA utilisés

Journal des demandes significatives faites à l'assistant (Claude Code), dans l'ordre.

1. Comprendre l'énoncé : rappel de ce qu'est un plan d'actions et de ce qui est attendu.
2. Rappel des notions DDD, Feature-Sliced Design, Nx, dump de base.
3. Vérifier que l'environnement de développement est prêt (install, Docker/Postgres, build, serve, tests).
4. « Renseigne-toi via des sources fiables, sans inventer, sur comment écrire et gérer les fichiers d'instructions IA ; préciser le contexte du test ; donner l'encadrement DDD et FSD ; ordre : besoins fonctionnels → backend en TDD → frontend ; commit/push réguliers selon les recommandations ; si on ne sait pas, le dire clairement. »
5. « La liste des besoins fonctionnels n'est pas le format le plus adapté pour développer : existe-t-il un format standard qui permet en plus de combler les trous ? » → user stories + Example Mapping + table de transitions + matrice RBAC + Gherkin (sources vérifiées).
6. « Je valide, fais ça » → rédaction de `docs/specs/`.
7. « Tu as ajouté une US (se connecter) : pourquoi celle-là et pas d'autres ? » → explication du marqueur [Implicite].
8. Réponses aux questions Q1–Q19, avec demandes de recherche sourcée sur : suppression physique/logique dans le domaine qualité/audit (Q6), gouvernance des admins (Q10), authentification standard (Q12), modifications concurrentes (Q15), vocabulaire User/Member (Q17).
9. Validation finale des choix → consignation dans `docs/decisions.md` (D2–D14), mise à jour des specs et rédaction des scénarios Gherkin (`docs/specs/features/`).
10. Ajout de deux règles de méthode : « ne pas réinventer la roue, se renseigner avant d'attaquer » et « recenser et suivre les normes (sécurité, ISO, domaine santé) ; si non demandé, au moins noter et prévoir » → règles n°2 et n°3 de `AGENTS.md`.
11. « Oui » à la recherche des normes → 4 recherches parallèles (sécurité, données de santé, qualité, accessibilité) → `docs/compliance.md` et questions Q20–Q27.
12. Validation de Q20–Q27 → décisions D15–D22.
13. « Avant d'attaquer, fait-on aussi la recherche pour la règle n°2 (ne pas réinventer la roue) ? » → 3 recherches parallèles (outillage Nx, backend, frontend) → `docs/stack.md`, questions S1–S8.
14. Questions sur le code maison (« t'es sûr qu'on doit le faire nous-mêmes ? »), CI jugée inutile, tests et lint automatiques via hooks, puis demande d'une stratégie de tests front sourcée où chaque besoin est testé automatiquement → recherches style/toasts et tests front, essai de vitest-cucumber sur nos `.feature` → décisions D23–D27.
15. « go » sur le plan d'outillage → cible `test` backend (Vitest + SWC), ESLint flat config, hooks husky + commitlint ; preuves exécutées : scénario manquant rouge, filtre `@back-only`, message invalide et test rouge refusés par les hooks.
16. « go » sur le plan backend (tranches 1 à 5) → tranche 1 `feat/action-lifecycle` : décisions D28–D30, table de transitions et agrégat `Action` en TDD, cas d'usage `ChangeActionStatus` / `RejectValidation`, scénarios d'`action-lifecycle.feature` joués au niveau application, test de contrat du repository (réutilisable pour TypeORM) ; preuves : suite verte, couverture > 80 %, scénario retiré → `ScenarioNotCalledError`.
17. « Tu as tout ce qu'il faut, déroule » → tranche 2 `feat/action-plans` : agrégat `ActionPlan`, édition et suppression logique d'une action, repositories et contrats, cas d'usage et lectures, scénarios d'`action-plans.feature` ; longueurs D11 et décision D31 proposées ; ajout de `typecheck` aux hooks (les specs n'étaient pas typées) ; ajout à la spec de l'exemple « Alice modifie un plan », qui manquait.
18. Suite du « déroule » → tranche 3 `feat/identity` : domaine (email, politique de mot de passe, `User`, `Membership`), hacheur scrypt, liste interdite, cas d'usage et scénarios d'`accounts-and-members.feature` ; décision D32. Points vérifiés aux sources pendant la tranche : NIST rev4 impose NFC (et non NFKC) ; la liste SecLists des 10 000 plus courants ne contient qu'une entrée ≥ 15 caractères, remplacée par une liste filtrée ; `maxmem` de scrypt ; hachage factice (OWASP Authentication). Écueils : le Contexte d'une règle vitest-cucumber s'exécute avant `BeforeEachScenario` ; gitleaks a bloqué un commit sur un mot de passe de test ressemblant à une clé (faux positif corrigé en changeant la valeur, hook non contourné).
19. Suite du « déroule » → tranche 4 `feat/persistence` : entités TypeORM séparées du domaine, update conditionnel sur la version, transactions par `@nestjs-cls/transactional`, migration initiale (contraintes nommées, FK composite, index partiel), migrations au démarrage, contrats de repository rejoués sur PostgreSQL 16 (Testcontainers) au pre-push ; décision D33. Écueils : nom automatique d'une FK composite (migration régénérée après `foreignKeyConstraintName`) ; SWC n'émet pas la métadonnée d'injection d'un alias de type (repéré par les tests d'intégration).
20. « Continue, t'as tout ce qu'il faut pour terminer » → tranche 5 `feat/http-api` : controllers et DTO, guard de session (cookie JWT relu en base, renouvellement glissant), guard d'`Origin`, `@IfMatch()` (412/428), filtre RFC 9457, throttling par IP et par compte, logs de sécurité, Swagger, e2e Supertest sur la vraie application et PostgreSQL 16 ; décision D34. Écueils : `isolatedModules` exige `import type` pour les interfaces dans les signatures décorées ; un agent HTTP ne renvoie pas un cookie `Secure` en http ; `@nestjs/throttler` suffixe `Retry-After` du nom du throttler.
21. Suite du « continue, t'as tout ce qu'il faut pour terminer » → frontend `feat/frontend` : FSD (pages, entities, widget de mise en page, shared), client `fetch` typé par le contrat OpenAPI généré, formulaires zod, dialogue React Aria, toasts Radix ; les trois `.feature` joués côté front contre une fausse API MSW, matrice des droits par rôle, axe-core sur chaque page, 2 parcours Playwright contre le vrai backend ; Steiger ajouté aux hooks ; décision D35. Écueils : vitest-cucumber fait de chaque étape un test (nettoyage automatique de Testing Library désactivé, nettoyage par scénario) ; sous jsdom, `URL` est celui de jsdom et `fileURLToPath` le refuse ; MSW 3 renomme `onUnhandledRequest` en `onUnhandledFrame` ; Steiger refuse les segments `providers` et `store` ; un heredoc shell trop long a échoué, fichiers réécrits un par un.
